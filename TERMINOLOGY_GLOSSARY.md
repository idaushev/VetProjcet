# TERMINOLOGY GLOSSARY

Словарь терминов интерфейса. Нужен, чтобы уже достигнутая унификация не
разъезжалась: предыдущая итерация точечно убрала расхождения
(«Визитов нет» → «Приёмов нет», «Клиент» → «Владелец»), но правила, к которому
сверяются новые тексты, не было. Это оно.

**Как пользоваться:** перед добавлением нового текста в интерфейс — сверить
термин с таблицей. Если понятия в таблице нет, добавить его сюда вместе с
правкой.

---

## Основные сущности

| Понятие | Встречалось в коде | Принято | Причина |
|---|---|---|---|
| Медицинский приём животного | Приём, визит, посещение | **Приём** | Основной термин продукта (`visits`, «Новый приём», «Приёмы»). «Визит» уже вычищен из пустых состояний |
| Запланированное время в расписании | Запись, бронирование | **Запись** | Отдельная сущность (`appointments`); запись ≠ приём — запись может не состояться |
| Человек, которому принадлежит животное | Владелец, клиент | **Владелец** | «Клиент» уже заменён; «владелец» точнее по смыслу и совпадает с названием раздела |
| Животное | Животное, пациент, питомец | **Животное** — в интерфейсе клиники<br>**Питомец** — в кабинете владельца | Осознанное исключение: владельцу «питомец» ближе, клинике — «животное» (`pets`, раздел «Животные») |
| Сотрудник, ведущий приём | Врач, доктор, специалист | **Врач** | Совпадает с полем формы и отчётами («Заработок по врачам») |
| Строка приёма (услуга/товар) | Позиция, услуга, товар | **Позиция** | Когда речь о строке счёта. «Услуга»/«Препарат» — когда о типе |
| Результат исследования | Результат, анализ | **Результат** — запись в системе<br>**Анализ/исследование** — сама процедура | `visit_results`; различие важно: результат может быть протоколом или файлом |
| Шаблон протокола исследования | Протокол, шаблон | **Шаблон протокола** | `protocol_templates` |
| Товарное движение | Движение, операция, транзакция | **Движение** | `stock_movements`, вкладка «Движения» |
| Файл, приложенный к приёму | Вложение, скан, файл | **Вложение** | `attachments`; «скан» — частный случай |

## Действия

| Действие | Встречалось | Принято | Причина |
|---|---|---|---|
| Создать приём | Новый приём | **+ Новый приём** | Уже конкретно, не менять |
| Создать запись | Запись | **+ Запись** | Уже конкретно |
| Создать владельца/животное/… | **+ Добавить** | **+ Владелец**, **+ Животное**, **+ Вакцинация**, **+ Сотрудник** | UX-020: «Добавить» не говорит, что появится, и противоречит соседним конкретным подписям |
| Сформировать отчёт | Сформировать | **Сформировать отчёт** | Уже исправлено предыдущей итерацией |
| Удалить | Удалить, убрать | **Удалить** | «Убрать» не использовать |
| Завершить приём | — | **Завершить приём** | Появится вместе с F1/VET-003 |

## Статусы

| Статус | Где | Принято | Примечание |
|---|---|---|---|
| Ожидается результат | `visit_results.status = pending` | **Ожидается** | Виден на дашборде как «незаполненный результат» |
| Результат внесён | `visit_results.status = done` | **Готов** | |
| Приём не завершён | *не существует* | **Черновик** | Появится с F1; см. VET-003 |
| Приём завершён | *не существует* | **Завершён** | Появится с F1 |
| Запись в расписании | scheduled / confirmed | **Запланирована / Подтверждена** | |
| Животное на лечении | `treatment_until >= today` | **На лечении** | Вычисляемое состояние, не поле |

## Термины, которые НЕ являются синонимами

Важно не «унифицировать» их по ошибке:

| Пара | Разница |
|---|---|
| **Запись** ≠ **Приём** | Запись — план в расписании; приём — состоявшаяся медицинская работа. Запись может не превратиться в приём |
| **Результат** ≠ **Вложение** | Результат — запись со значениями или заключением; вложение — файл. Результат может ссылаться на вложение, но это разные сущности |
| **Позиция приёма** ≠ **Назначение** | Позиция — строка счёта; назначение — клиническое указание. Сейчас они не разделены, и это зафиксировано как VET-004/VET-012 |
| **Движение** ≠ **Позиция приёма** | Движение — товарный учёт; позиция — счёт приёма. Связи между ними сейчас нет by design |
| **Диагноз** ≠ **Состояние пациента** | Разные поля приёма (`diagnosis`, `patient_condition`) |

## Правила формулировок

1. **Кнопка называет результат, а не процесс.** «Сохранить приём», а не «Готово».
2. **Не сокращать до абстракции.** «Добавить» без объекта — только если объект
   очевиден из немедленного контекста (например, «+ Позиция» внутри формы приёма).
3. **Подтверждение удаления состоит из двух частей:** что удаляем (заголовок) и
   что произойдёт (тело). Пустое тело — ошибка (UX-025).
4. **Пустое состояние отвечает на три вопроса:** что здесь, почему пусто, что
   сделать.
5. **Термин один на весь продукт.** Исключение — кабинет владельца, где
   допустимо «питомец»; исключение зафиксировано выше явно.

## Открытые вопросы терминологии

- **«Назначение»** — как называть структурированную сущность после F4:
  «Назначение» или «Лист назначений»? Решается вместе с вопросом 1 клинике.
- **«Жалоба»** — если поле повода обращения будет выделено (VET-005), выбрать
  между «Жалоба» и «Повод обращения». Зависит от ответа на вопрос 5.
