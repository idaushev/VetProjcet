# Аудит безопасности VetProject

Дата: 2026-09-02 · версия приложения 2.83.0 · ветка `fix/audit-critical-security`

Аудит охватывает: аутентификацию и сессии, модель прав, синхронизацию,
портал владельцев, телеграм-бота, вложения, транспорт, заголовки, инъекции,
XSS, лимиты и обращение с секретами.

Помеченное «**подтверждено**» воспроизведено на живом стенде, а не выведено
из чтения кода.

## 1. Хранимая XSS через текстовые поля → кража сессии · ВЫСОКИЙ

**Где.** Разметка собирается конкатенацией строк, и значения подставляются
внутрь JS-строки, которая живёт в HTML-атрибуте обработчика:

```js
// frontend/js/pages.js:1923
'<button onclick="event.stopPropagation();VetPages.deleteItem(\'' + it.id + '\',\'' + esc(it.name) + '\')">'
```

`esc()` переводит `'` в `&#39;`, и для обычного текста этого достаточно. Но
браузер **HTML-декодирует значение атрибута до того, как отдаст его
JS-парсеру**: `&#39;` снова становится `'`, строка разрывается, дальше идёт
код атакующего. Экранирование здесь не работает в принципе — нужен другой
способ передачи значения.

**Масштаб.** 59 мест подставляют выражение в JS-строку внутри обработчика.
В 55 из них это UUID — не эксплуатируется. Опасны 5, где подставляется
вводимый человеком текст:

| Файл | Что подставляется |
|---|---|
| `pages.js:1923` | название позиции каталога → `deleteItem` |
| `pages.js:1998` | имя сотрудника → `deleteStaff` |
| `pages.js:3971` | телефон владельца → `location.href='tel:…'` |
| `pages.js:4086` | телефон владельца → `callOwner` |
| `pages.js:4228` | телефон владельца → `location.href='tel:…'` |

**Подтверждение.** Позиция каталога с названием

```
Витамины');window.__XSS_ITEM=document.cookie||'fired';//
```

даёт в DOM обработчик, который браузер компилирует так:

```js
function onclick(event) {
  event.stopPropagation();
  VetPages.deleteItem('bcf8cb53-…','Витамины');
  window.__XSS_ITEM=document.cookie||'fired';//')
}
```

После клика по кнопке удаления `window.__XSS_ITEM === 'fired'` — внедрённый
код выполнен.

**Последствие.** Токен сессии лежит в `localStorage['vet-auth'].token`,
доступен из JS, живёт 90 дней (`sessionTTL`). Там же `verifier` — материал
для офлайн-входа. Пользователь с правом `items:edit` (регистратура) заводит
позицию с нагрузкой; первый администратор, нажавший «удалить», отдаёт свой
токен. Это эскалация привилегий до админа внутри клиники, а не только
«кто-то что-то нарисовал на экране».

**Что делать.** Экранированием проблему не закрыть. Правильный путь —
убрать данные из атрибута: класть значение в `data-`-атрибут (там
`esc()` работает корректно, потому что значение не попадает в JS-парсер) и
навешивать обработчик делегированием, как уже сделано в некоторых местах
проекта. Начать с пяти строк из таблицы, дальше — по правилу бойскаута.

Смягчающее обстоятельство: требуется учётная запись сотрудника и клик
жертвы. Обработчиков без взаимодействия (`onerror`, `onload`) в коде нет —
проверено.

## 2. Токен сессии попадает в лог сервера · СРЕДНИЙ

`authMiddleware` принимает токен не только в заголовке, но и в query —
запасной канал для ссылок, куда заголовок не вставить (открытие скана в
новой вкладке, `pages.js:1712`):

```go
token = strings.TrimSpace(r.URL.Query().Get("t"))   // backend/auth.go:286
```

А `loggingMiddleware` пишет полный URI:

```go
a.logger.Printf("%s %s %s", r.Method, r.URL.RequestURI(), …)  // backend/handlers.go:202
```

**Подтверждено:** запрос `GET /attachments?t=SEKRETNIY_TOKEN_12345` кладёт
токен в лог дословно. То же касается `?pt=` — портальных сессий
(`portal.go:218`).

Сейчас лог идёт в `os.Stdout`, в проде — в окно консоли, файла нет. Но любой
перезапуск под сервисной обёрткой (NSSM, `> server.log`) превращает лог в
файл с рабочими токенами на 90 дней. Плюс токен виден в истории браузера и
уходит в `Referer`.

**Что делать.** Маскировать `t` и `pt` в строке лога. Отдельно стоит подумать
о коротких одноразовых ссылках на вложения вместо токена в URL.

## 3. Перечисление клиентской базы через портал · СРЕДНИЙ

`handlePortalLogin` отвечает по-разному:

* номера нет в базе → `404 «Номер не найден»`
* номер есть, код неверный → `401 «Неверный или просроченный пароль»`

Троттлинг при этом навешен только на второй случай: `portalLoginThrottle.fail()`
вызывается после неудачной проверки кода, а ветка «номер не найден» выходит
раньше (`portal.go:120-123`).

**Подтверждено:** 20 запросов подряд без пауз — 20 ответов `404`, ни одного
`429`.

**Последствие.** Атакующий перебирает диапазон номеров и получает список
телефонов, чьи владельцы обслуживаются в клинике. В медицинском контексте
сам факт обращения — уже персональные данные.

**Что делать.** Отвечать одинаково в обоих случаях и звать `fail()` до
выхода из ветки «номер не найден».

## 4. Нет ограничения размера тела JSON · СРЕДНИЙ

`decodeJSON` (`handlers.go:237`) читает тело без `http.MaxBytesReader`. Все
JSON-эндпоинты — `/pets`, `/owners`, `/visits`, `/items`, `/portal/*` —
буферизуют запрос целиком.

`pets.photo` — base64-строка в самой записи; лимит 200 КБ стоит только на
клиенте (`pages.js:5164`), на сервере в `/pets` его нет вовсе. Портальный
`/portal/pets/{id}/photo` лимит проверяет (400 000 символов), но **после**
`decodeJSON`, то есть после того, как всё тело уже в памяти.

Есть где сделано правильно: `/sync/push` ограничен 8 МБ, вложения —
`MaxBytesReader`. Не хватает того же в общем декодере.

**Последствие.** Аутентифицированный пользователь исчерпывает память
сервера. Мягче, но неприятнее: раздутое фото уезжает в базу и оттуда на
каждый планшет при следующем pull.

## 5. Отсутствуют заголовки безопасности · СРЕДНИЙ

Не отдаётся ни один: `Content-Security-Policy`, `X-Content-Type-Options`,
`X-Frame-Options` / `frame-ancestors`, `Referrer-Policy`.

* Без `X-Frame-Options` приложение встраивается в чужой iframe — кликджекинг.
* Без `Referrer-Policy` токен из находки №2 утекает во внешние ссылки.
* CSP усложнила бы находку №1, но осмысленная политика потребует отказа от
  инлайновых обработчиков, а на них построен весь интерфейс. Это следствие
  той же работы, что и по №1, а не отдельная задача.

Дешёвые и безопасные прямо сейчас: `nosniff`, `X-Frame-Options: DENY`,
`Referrer-Policy: same-origin`.

## 6. `Access-Control-Allow-Origin: *` · СРЕДНИЙ

```go
w.Header().Set("Access-Control-Allow-Origin", "*")   // handlers.go:186
```

Куки не используются, авторизация идёт через заголовок — классический CSRF
не проходит. Но `*` разрешает любому сайту, открытому у сотрудника,
обращаться к серверу клиники и читать ответы там, где токен не нужен, а
также прощупывать сеть. Сервер живёт в локальной сети клиники; ограничить
источник до собственного адреса ничего не ломает.

## 7. Портал: нет выхода и нет отзыва сессий · СРЕДНИЙ

* `DELETE FROM owner_sessions` не встречается нигде — эндпоинта выхода нет.
* Протухшие строки не удаляются: таблица растёт бесконечно.
* Отозвать доступ нельзя. Владелец сменил номер, потерял телефон, перестал
  быть клиентом — его сессия живёт 90 дней (`portalSessionTTL`).

Сессии сотрудников чистятся при смене пароля и прав (`auth.go:705-749`), но
фонового удаления протухших нет и там.

```go
canPush := func(table string) bool {
    return pushUser == nil || pushUser.tableLevel(table) >= permLevels["create"]
```

## 9. Пароль первого администратора · НИЗКИЙ

`bootstrapAdmin` печатает пароль в лог и кладёт в `data/ADMIN-PASSWORD.txt`
(права 0600, в веб-корень не попадает). Файл не удаляется автоматически
после первой смены пароля — остаётся лежать рядом с базой и попадает в
резервные копии.

## 10. `/diagnoses` без проверки прав · НИЗКИЙ

`pathTable` (`auth.go:308`) не знал этого пути, и `deniedByPermissions`
возвращал «доступ есть»: любой вошедший правил шаблоны диагнозов независимо
от выданных прав.

Уточнение к первоначальной формулировке: `/tasks` попал в эту находку зря.
Задач нет в модели прав вовсе — это общий список дел клиники, доступный всем
сотрудникам по замыслу. Обхода прав там не происходит, обходить нечего.

## Что сделано хорошо

Отмечаю, чтобы при правках это не сломали:

* **Умолчание «запретить»** в `authMiddleware`: защищено всё, кроме явного
  белого списка `authExempt`.
* **Пароли** — PBKDF2-HMAC-SHA256, 150 000 итераций, случайная соль,
  сравнение через `subtle.ConstantTimeCompare`.
* **Токены** — 32 байта из `crypto/rand`, в базе только SHA-256, оригинал не
  хранится. `math/rand` не используется нигде.
* **SQL-инъекций нет.** Везде плейсхолдеры; конкатенируются только
  константные фрагменты. Три места с динамическим именем таблицы
  (`handleAuthorship`, `stampAuthor`, `clientWinsVersion`) берут имя из
  белого списка или из кода, не из запроса. Корзина — тоже белый список.
* **Вложения** — тип определяется по содержимому (`http.DetectContentType`),
  белый список из пяти типов, `text/html` и SVG не пройдут; путь проверяется
  на выход за корень; в синхронизации вложения только на чтение, поэтому
  подделать `mime_type` через push нельзя.
* **Троттлинг по аккаунту, а не по IP** — с внятным обоснованием: все
  планшеты клиники за одним роутером.
* **Портал** — IDOR закрыт: каждый хендлер зовёт `requirePortalOwner`, а
  доступ к чужому питомцу отсекает `petBelongsToOwner`. Проверены все
  восемь хендлеров.
* **Телеграм** — long-poll вместо вебхука, публичной точки входа нет; токен
  бота наружу отдаётся замаскированным.
* **Коды портала** — 6 цифр из `crypto/rand`, одноразовые, предыдущие
  гасятся при выдаче нового, TTL ограничен.
* **TLS** — `MinVersion: TLS 1.2`.

## Чем закрыто

**№1 — XSS.** Введено правило: *в inline-обработчик подставляем только
идентификатор, никогда свободный текст*. `deleteItem` и `deleteStaff` теперь
принимают id и сами достают название из уже загруженного списка; `callOwner`
принимает id владельца и читает номер из локальной базы; два инлайновых
`location.href='tel:…'` заменены вызовом того же `callOwner`. Проверено той
же нагрузкой, что срабатывала до правки: в атрибуте остаётся только UUID,
внедрённый код не выполняется, а текст подтверждения удаления по-прежнему
показывает настоящее название.

**№2 — токен в логе.** `redactTokens` заменяет значения `t` и `pt` на
`redacted` перед записью. Проверено: `?t=SEKRETNIY_TOKEN_12345` попадает в
лог как `?t=redacted`. Добавлен `Referrer-Policy: same-origin`, чтобы тот же
токен не уходил в заголовке перехода.

**№3 — перечисление клиентов.** Один текст ошибки и один код (401) на оба
случая, и неизвестный номер тоже идёт в счётчик попыток. Проверено: ответы
для существующего и несуществующего номера совпадают побайтово, а шестая
попытка по одному номеру получает 429.

**№4 — размер тела.** Потолок 2 МБ в `decodeJSON`, с отдельным понятным
сообщением: обрезанное тело раньше давало «invalid json: unexpected EOF», по
которому непонятно, что фото просто тяжёлое.

**№5 — заголовки.** `Content-Security-Policy`, `X-Content-Type-Options`,
`X-Frame-Options: DENY`, `Referrer-Policy: same-origin` на каждый ответ. CSP
оставлена мягкой по `script-src` (`unsafe-inline`): интерфейс построен на
инлайновых обработчиках, убрать это без их переписывания нельзя. Зато
`connect-src 'self'` уже мешает внедрённому скрипту отправить украденный
токен наружу, а `frame-ancestors 'none'` закрывает кликджекинг. Проверено,
что печать не сломалась: инлайновые `<style>`, `<script>`, `onclick` и
`data:`-картинки внутри печатного iframe работают.

**№6 — CORS.** Заголовок выдаётся только своему же источнику, чужому не
выдаётся вовсе. Проверено с `Origin: https://evil.example`.

**№7 — портал.** Добавлен `POST /portal/logout`, гасящий сессию на сервере
(проверено: `/portal/me` отвечает 200 до выхода и 401 после). Кнопка «Выйти»
зовёт его, а не просто забывает токен в браузере. Сессии владельца удаляются
вместе с его карточкой. Протухшие сессии обеих таблиц выметаются тем же
суточным циклом, что делает бэкап.

**№8 — `canPush`.** Умолчание стало «запретить». Правка вскрыла, что
sync-тесты ходили в хендлер вообще без пользователя — теперь они кладут его
в контекст, как это делает `authMiddleware`, то есть проверяют настоящий
путь. Добавлен тест: push без пользователя не принимает ни одной записи.

**№9 — пароль администратора.** `data/ADMIN-PASSWORD.txt` удаляется, как
только администратор сменил пароль.

**№10 — права на шаблоны диагнозов.** `/diagnoses` отнесён к правам приёмов:
кто ведёт приёмы, тот и правит шаблоны. Пользователь с `visits: view` теперь
читает шаблоны, но не меняет их.

Регрессионные тесты на находки 2, 3, 5, 6, 8 — в `backend/security_test.go`.

## Что осталось

* ~~**Инлайновые обработчики.**~~ Закрыто в 2.85.0: все 151 инлайновый
  обработчик и оба инлайновых `<script>` переведены на делегирование
  (`frontend/js/actions.js`), из `script-src` убран `unsafe-inline`.
  Подробности — в разделе «Инлайновые обработчики» ниже.
* **Инлайновые `style`-атрибуты — решено оставить (2.86.0).** Опасную форму,
  внедрённый `<style>`, закрыли отдельно: все семь своих блоков вынесены в
  `/css/*.css`, и `style-src-elem 'self'` больше не пускает чужие. Остались
  336 атрибутов `style=`, под них держится `style-src-attr 'unsafe-inline'`.

  Почему не тронули. Атрибут можно внедрить только через инъекцию HTML, а её
  закрывает `esc()`; канала утечки нет — `script-src 'self'`,
  `img-src 'self' data: blob:` и `connect-src 'self'` уже стоят. Цена же
  высокая: 236 уникальных атомов «свойство:значение» (не десяток повторов, а
  длинный хвост) плюс 44 `display:none`, которые не оформление, а состояние —
  JS переключает видимость в 81 месте, и **25 из них показывают элемент через
  `style.display = ''`**. Перенос начального «скрыто» в класс или в атрибут
  `hidden` сломал бы именно эти 25: сброс инлайнового свойства перестал бы
  показывать элемент, и панель осталась бы молча невидимой.

  Частичная работа тут ничего не даёт: `style-src-attr` можно ужесточить,
  только когда убраны все 336. Если возвращаться — начинать с 81 места
  переключения `display`, а не с разметки.
* **Токен в строке запроса.** `?t=` остаётся запасным каналом для ссылок на
  сканы. Из лога и из `Referer` он больше не утекает, но в истории браузера
  остаётся. Полное решение — короткие одноразовые ссылки на вложение вместо
  токена сессии.
* **Срок сессии 90 дней** и у сотрудников, и у владельцев. Для клиники с
  планшетом это осознанный компромисс (офлайн-первый режим), но при потере
  устройства окно большое. Отзыв сейчас возможен только через смену пароля
  (сотрудник) или удаление карточки либо выход (владелец).

## Инлайновые обработчики: как закрыли (2.85.0)

Находка 1 была залатана точечно — пять мест, где в обработчик подставлялся
свободный текст. Но пока инлайновые обработчики есть в принципе, CSP обязана
разрешать `script-src 'unsafe-inline'`, а значит не мешает и внедрённому
скрипту. Правило «подставляем только идентификаторы» при этом держалось на
внимательности человека.

Перепись показала **151 обработчик** в семи файлах, **два инлайновых
`<script>`** в `index.html` (262 строки) и **один** в `portal.html` (305), а
также две функции, которые принимали код строкой: `emptyState(…, ctaOnclick)`
и пункты `rowMenu({onclick})`.

Отдельная находка по ходу работы: `rowMenu` подставлял в код ФИО владельца и
кличку животного — те же две дыры, что и в находке 1. Прежний сканер их
пропустил, потому что строка там собиралась двойными кавычками и не совпала с
искомым шаблоном. То есть «пять мест» было заниженной оценкой.

**Что сделано.** Появился `frontend/js/actions.js` — реестр действий и один
делегат на `document`. Элемент объявляет имя и данные:

```html
<button data-act="item.delete" data-id="…">Удалить</button>
```

Значения атрибутов нигде не разбираются как код. Незарегистрированное имя не
делает ничего и пишет предупреждение в журнал.

Побочный выигрыш: делегат берёт **ближайшего** предка с `data-act`, поэтому
кнопка внутри кликабельной строки перекрывает действие строки сама собой —
`event.stopPropagation()` из разметки исчез (было 14 мест).

**Проверка покрытия.** 106 имён в разметке, 106 в реестре. Сверка
автоматическая: скрипт собирает имена из исходников и сравнивает с ключами
`VetActions.register`.

**Проверено в браузере** при уже строгой CSP: 13 страниц отрисовываются,
инлайновых атрибутов в DOM ноль, нарушений CSP в консоли нет; клик по строке
открывает карточку, а кнопка внутри строки — форму (то есть «ближайший
выигрывает» работает); меню «⋯» открывается и не схлопывается сразу; проверка
чипа, сворачивание секций, пресет следующего приёма, кнопка сброса поиска
работают; прежняя XSS-нагрузка отображается как текст и не выполняется.

**Осталось** от этой работы: `style-src` по-прежнему с `unsafe-inline`
(инлайновые `style`-атрибуты), и кнопка «Распечатать» внутри печатного
документа получает обработчик из родителя — сам диалог печати в тестовом
браузере не воспроизводится, поэтому проверена только проводка.
