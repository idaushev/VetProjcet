# VetClinic — архитектура

Документ для двух читателей: человека, который собирается что-то менять, и
агентов-стражей (`.claude/agents/`), которые проверяют изменения. Поэтому
главная часть — **инварианты**: пронумерованные утверждения, которые должны
оставаться истинными после любого коммита. Нарушение инварианта — ошибка,
даже если всё работает на экране.

Подробности по подсистемам: `docs/SYNC.md`, `docs/MODULES.md`,
`docs/DATABASE.md`, `docs/PWA.md`. Что делаем сейчас — `docs/PRODUCT.md`.

---

## 1. Общая схема

```
 Планшет (PWA)                                   Сервер (Go, один процесс)
┌──────────────────────────────────────┐        ┌───────────────────────────────┐
│ UI: pages.js, ui.js, modules/*.js    │        │ handlers_*.go   REST          │
│        │ fetch('/owners' …)          │        │ handlers_sync.go /sync/push   │
│        ▼                             │        │                  /sync/pull   │
│ app.js — перехватчик fetch           │  HTTP  │ sync_registry.go реестр       │
│        │ пишет локально, сразу       │◄──────►│ auth.go         права, сессии │
│        ▼                             │ когда  │ modules.go      реестр модулей│
│ db.js — IndexedDB + sync_queue       │ онлайн │        │                      │
│        │ фоном                       │        │        ▼                      │
│ sync.js — push очереди, pull дельты  │        │ SQLite (WAL), db.go миграции  │
│ service-worker.js — статика офлайн   │        └───────────────────────────────┘
└──────────────────────────────────────┘
```

Путь записи всегда один: **UI → IndexedDB → очередь → сервер.** Никогда
UI → API → кэш.

## 2. Ядро и модули

| | Что входит | Где объявлено |
|---|---|---|
| **Ядро** (всегда) | auth, синк, владельцы, животные, приёмы (+ позиции, назначения, результаты, вложения), вакцинации, каталог, персонал, расписание, задачи, справочники | `sync_registry.go` (`coreSyncEntities`), `db.js` (`CORE_ENTITY_STORES`) |
| **Модули** (тумблер) | `warehouse`, `portal`, `telegram` | `backend/modules.go` (`moduleRegistry`), `frontend/js/modules.js` (`VetModules.register`) |

`frontend/js/modules/{chips,schedule,print,protocols}.js` — это **вынесенный
код ядра**, а не модули с тумблером. Не путать.

Модуль добавляется в одном месте на каждой стороне; тумблер в Настройках
появляется сам. Контракт — `docs/MODULES.md`.

## 3. Сущность и её четыре точки записи

У каждой синкаемой сущности есть:

| Точка | Сервер | Клиент |
|---|---|---|
| Создание | `handlers_<x>.go` POST | перехватчик `app.js` |
| Правка | `handlers_<x>.go` PUT | перехватчик `app.js` |
| Синк | `pushX` / `pullX`, строка в `sync_registry.go` | `sync.js` |
| Чтение | GET, `pullX` | стор в `db.js` |

Плюс сквозные места, которые обязаны знать о сущности:

- схема — `db.go` (CREATE + идемпотентные ALTER в `migrations`);
- права синка — поле `PermTable` в строке реестра (`sync_registry.go`), его
  читают и push, и pull; ожидаемое право — в `TestEverySyncEntityDeclaresPermission`;
- права REST — `pathTable` в `auth.go` (маршрут без строки там не проверяется вовсе);
- стор IndexedDB — `CORE_ENTITY_STORES` или `stores` модуля;
- права в интерфейсе — `PERM_TABLES` в `pages.js` (только если у сущности своя
  строка прав; спутники её не имеют).

## 4. Инварианты

### Офлайн

- **A1.** Ни одна основная операция (приём, владелец, животное, запись,
  вакцинация, касса) не требует сети. Запрос к API из UI в обход
  перехватчика — только с `X-Bypass-Local: 1` и только для служебного.
- **A2.** Синк не блокирует интерфейс и не перерисовывает экран, если данные
  не изменились (`CLAUDE.md`, п.5). Надгробия, пришедшие повторно, —
  не изменение.
- **A3.** Ошибка синка одной сущности не останавливает остальные.

### Данные

- **D1.** Бизнес-сущности не удаляются физически: `is_deleted` / `deleted_at`.
- **D2.** Каждая синкаемая запись несёт `id` (UUID), `updated_at`,
  `client_updated_at`, `version`, `device_id`, `is_deleted`. Конфликт решается
  по времени клиента (`docs/SYNC.md`, память «Конфликты синхронизации»).
- **D3.** Миграции только идемпотентны (`CREATE … IF NOT EXISTS`,
  `ADD COLUMN`, пропуск «duplicate column»). Никаких `DROP`/переименований
  колонок с данными без плана отката и проверки на копии боевой базы.
- **D4.** Для каждой сущности список колонок и список значений в SQL
  совпадают во всех четырёх точках записи (`CLAUDE.md`, п.3). Правка одной
  точки — просмотр всех четырёх.
- **D5.** Ссылки на строки приёма (`visit_items`) не опираются на их `id`:
  строки пересоздаются при каждом сохранении. Ключ — признак, переживающий
  правку (`seq`, `item_id`) (`CLAUDE.md`, п.4).
- **D6.** Медицинская запись, которая переживёт свой справочник, хранит
  снимок того, по чему её оценивали (`fields_snapshot`) (`CLAUDE.md`, п.6).
- **D7.** Деньги: `total_amount` уже за вычетом скидки; `cost_price` всегда
  в тенге, процентный режим пересчитывается в `resolveCost`.

### Доступ

- **P1.** Права проверяются на сервере — в REST **и** в `/sync/push`
  **и** в `/sync/pull`. Скрыть в UI недостаточно: IndexedDB видна из консоли.
- **P2.** Отображение «сущность → право» одно — `PermTable` в реестре синка — и
  совпадает с `pathTable` для REST. Спутник
  (позиции, назначения, результаты, вложения, запись на время) наследует
  право родителя. Право, которого нет в настройках пользователя, по умолчанию `edit`;
  маршрут, которого нет в `pathTable`, не проверяется. Значит, **забытый
  спутник открыт всем.**
- **P3.** Выключенный модуль: скрыт UI, 404 на маршрутах, нет в `/sync/pull`,
  код, читающий его стор, не падает (`CLAUDE.md`, п.1, четыре пункта).
- **P4.** Суммы видны по праву `sums` (`all / own / selected`) — на сервере.

### Клиент

- **C1.** Версия приложения — одна: `APP_VERSION` в `service-worker.js`.
  Любая правка статики поднимает её, иначе планшет не получит изменение.
- **C2.** Интерфейс на русском, идентификаторы и схема — на английском,
  комментарии — на русском. Слова интерфейса — по `TERMINOLOGY_GLOSSARY.md`.
- **C3.** Отступы — шкала `--sp-1…8`, контролы — `--ctl-h`, тач-цели не
  меньше 44px. Брейкпоинты только опорные: 767 / 1023 / 1280 / 1440,
  `pointer: coarse`, `print`.
- **C4.** Без инлайновых обработчиков и `<style>` в разметке (CSP).
  `style.display` из JS допустим — это состояние.
- **C5.** Новый код не добавляется в `pages.js`, если у области уже есть
  файл в `js/modules/`. Новая крупная область — сразу своим файлом.

## 6. Как менять этот документ

- Новая подсистема, новая сущность ядра, новый модуль — строка в разделах 2–3.
- Новый урок, стоивший ошибки в проде, — инвариант в раздел 4 с кодом
  (A/D/P/C + номер). Номера не переиспользуются.
- Агенты-стражи ссылаются на коды инвариантов — не переименовывать.
